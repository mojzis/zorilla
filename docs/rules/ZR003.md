# ZR003 — no-assertion

## Why

A test that never asserts never fails — it only exercises code for side
effects. Pytest treats the absence of an exception as success, so a test
with no check is green forever. Every test needs at least one observable
postcondition.

The rule fires once per test function whose body contains none of:

- a bare or message-bearing `assert` statement;
- a call whose function's final identifier is a known assertion helper
  (e.g. `assertEqual`, `fail`), configurable via `extra_helpers`;
- a `with <expr>.raises(...)` or `with <expr>.warns(...)` context manager.

The walk descends into nested inline helpers. The finding points at the
test function's `def` line — the intent is "this whole test is
assertion-free".

## Positive example

```python
def test_does_nothing():       # ZR003 fires here
    setup()
    act()
```

## Negative example

```python
import pytest

def test_ok():
    assert value() == 1

def test_raises():
    with pytest.raises(ValueError):
        boom()
```

## Config

```toml
[tool.zorilla.rules.ZR003]
enabled = true
extra_helpers = ["expect", "verify"]
```

`extra_helpers` merges with the built-in unittest helpers. Matching is
by the final identifier of the call target, so `self.expect(...)` and
bare `expect(...)` both match.

## Suppression

Inline (on the `def` line, since that's where the finding is reported):

```python
def test_smoke():  # zorilla: ignore[ZR003]
    do_side_effect_only()
```

File-level:

```python
# zorilla: ignore-file
```
