# ZR008 — context-patch-stack

## Why

`@patch`-decorator towers (ZR006) aren't the only way a test piles on
setup — the same problem appears spelled with `with patch(...)` context
managers. Each layered `patch` adds one more thing the reader has to
track and one more piece of production internals the test is bound to
by string-path. When more than `max_patches` (default `3`) `patch`
context managers appear in a single test — whether stacked vertically
in nested `with` blocks or packed into one `with patch(), patch(), ...:`
clause — the code is overdue for a fixture that builds the whole mock
graph once.

This rule counts `patch`, `mock.patch`, and `unittest.mock.patch`
context-manager items inside a test function. `patch.object(...)` is
**not** counted — same exclusion as ZR006 — because targeted attribute
patches are a different shape of problem and conflating the two makes
the message harder to act on.

Threshold is **exclusive**: the default fires at 4 or more `patch`
context-manager items.

**Reported location**: the first qualifying `patch` `with_item`'s start
position. That's the top of the patch stack and the most actionable
target — pointing at a non-patch `with open(...)` further down would
mislead the reader.

## Positive examples

Four sequential nested `with patch(...)` blocks:

```python
from unittest.mock import patch

def test_many():
    with patch("app.db.connect"):
        with patch("app.cache.get"):
            with patch("app.logger.info"):
                with patch("app.clock.now"):   # ZR008 fires at the first patch
                    assert run()
```

Four `patch` items inside a single `with` clause:

```python
def test_many():
    with patch("a"), patch("b"), patch("c"), patch("d"):   # ZR008 fires
        assert run()
```

## Negative examples

Three `with patch(...)` at the default threshold — no fire:

```python
def test_ok():
    with patch("a"), patch("b"), patch("c"):
        assert run()
```

`with open(...) as f:` — not a `patch`, so it doesn't count:

```python
def test_reads_file():
    with open("fixtures/data.json") as f:
        assert json.load(f)
```

## Config

```toml
[tool.zorilla.rules.ZR008]
enabled = true
max_patches = 3
```

`max_patches` defaults to `3` — the rule fires on the 4th `patch`
context-manager item.

## Suppression

Inline (on the line of the first qualifying `patch`, which is where the
finding points):

```python
def test_legacy():
    with patch("a"):  # zorilla: ignore[ZR008]
        with patch("b"):
            with patch("c"):
                with patch("d"):
                    ...
```

File-level:

```python
# zorilla: ignore-file[ZR008]
```
