# ZR002 — sleep-in-test

## Why

Real time in tests is a race-condition generator: `time.sleep` and
`asyncio.sleep` either waste the suite's wall-clock budget or
occasionally fail under load. The fix is almost always to wait on a
condition (polling, event, mocked clock), not on a fixed duration.

The rule fires once per `sleep` call inside a test function body,
directly or nested in inline helpers. A call matches when its function
expression is a bare `sleep` identifier or any attribute access whose
final segment is `sleep` (covers `time.sleep`, `asyncio.sleep`,
`trio.sleep`, etc.).

## Positive example

```python
import time

def test_waits():
    trigger()
    time.sleep(1)       # ZR002 fires here
    assert done()
```

## Negative example

```python
from time import monotonic

def test_polls():
    trigger()
    deadline = monotonic() + 2.0
    while monotonic() < deadline:
        if done():
            return
    raise AssertionError("timed out")
```

## Config

```toml
[tool.zorilla.rules.ZR002]
enabled = true
```

Set `enabled = false` to disable. No other knobs.

## Suppression

Inline (offending line):

```python
def test_waits():
    time.sleep(1)  # zorilla: ignore[ZR002]
```

File-level:

```python
# zorilla: ignore-file
```
