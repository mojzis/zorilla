# ZR007 — empty-test

## Why

An empty test function — one whose body is just `pass`, `...`, a
docstring, or nothing executable — is almost always a leftover stub or
an accidentally-deleted body. It exercises no code, asserts nothing,
and still counts as a passing test, which gives a false sense of
coverage. Either fill it in or delete it.

The rule fires once per test function whose body contains no
executable statements. A body consisting solely of `pass`, an ellipsis
expression (`...`), or a docstring counts as empty.

Tests decorated with `@pytest.mark.skip` / `@pytest.mark.xfail` (at the
function or class level) are never flagged — the body is never executed.
The same applies to tests whose **first real body statement** (after any
leading docstring or comments) is a runtime skip call:
`self.skipTest(...)`, `self.skip(...)`, or `pytest.skip(...)`. Such tests
are unconditionally skipped at runtime; a placeholder-shaped body is
intentional. Note: `skipif`, bare `skip(...)`, and non-`self`/`pytest`
receivers are not matched.

## Positive example

```python
def test_todo():                   # ZR007 fires here
    pass

def test_stub():                   # and here
    """TODO: write this."""
```

## Negative example

```python
def test_does_something():
    assert compute() == 42
```

## Config

```toml
[tool.zorilla.rules.ZR007]
enabled = true
```

Set `enabled = false` to disable. No other knobs.

## Suppression

Inline (on the `def` line, where the finding is reported):

```python
def test_placeholder():  # zorilla: ignore[ZR007]
    pass
```

File-level:

```python
# zorilla: ignore-file
```
