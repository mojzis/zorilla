# ZR005 — mystery-guest

## Why

A "mystery guest" is an external resource a test silently depends on —
an absolute filesystem path, a real URL, a home-directory path. Such
tests are not hermetic: they pass or fail based on state the reader
cannot see from the test source. Replace mystery guests with fixtures,
`tmp_path`, in-memory fakes, or explicit test doubles.

The rule scans string literals inside test functions and fires on:

- absolute filesystem paths (`/etc/...`, `C:\...`);
- URLs with real schemes (`http://`, `https://`, `ftp://`, ...);
- home-directory paths (`~/...`, `$HOME/...`).

## Positive example

```python
def test_config_loads():
    cfg = load_config("/etc/myapp/config.toml")   # ZR005 fires here
    assert cfg.debug is False
```

## Negative example

```python
def test_config_loads(tmp_path):
    path = tmp_path / "config.toml"
    path.write_text("debug = false\n")
    cfg = load_config(path)
    assert cfg.debug is False
```

## Test data versus resources

Two shapes of literal are test data by construction and never fire:

- **Reserved, non-resolvable hosts** — a URL whose host ends in
  `.invalid`, `.test` or `.example` (RFC 2606 / RFC 6761). Nothing can
  be fetched from `https://example.invalid/project`, so the literal is
  synthetic whatever the test does with it. `example.com` is *not* in
  this set: it resolves, so a test that fetches it has a real network
  dependency. A suite that uses it as synthetic data says so locally
  with `allowed_prefixes = ["https://example.com"]`.
- **Direct argument of a parse-only call** — a literal passed straight
  to `urlparse`, `urlsplit`, `urljoin`, `urldefrag`, `PurePath`,
  `PurePosixPath` or `PureWindowsPath` (matched on the final identifier,
  so `urllib.parse.urlparse(...)` counts). These cannot open or fetch
  their argument. Only a *direct* argument qualifies:
  `urlparse(fetch("https://…"))` is whatever `fetch` does.

  ```python
  result = urlparse("https://api.example.com/project")   # not flagged
  path = PurePosixPath("/fictional/input.txt")           # not flagged
  ```

`Path` is deliberately **not** parse-only: `Path("/etc/x").read_text()`
is the canonical mystery guest, and a syntactic tool cannot see whether
a `Path` is later opened. A suite that builds `Path("/fictional/...")`
purely as parser or error-message input opts in with
`extra_pure_callees = ["Path"]`, accepting that a real
`Path("/etc/x").read_text()` in that suite will no longer be reported.
That is an explicit local policy, stated once in config, rather than a
blanket `/` prefix exemption that would hide every absolute path.

## Carve-outs

Beyond the allow-list, several structural patterns are silenced because
they recur in real test suites and represent fixture configuration rather
than live external access:

- **Assert message** — `assert cond, "/etc/msg"` failure explanations.
- **TestClient route** — first positional arg of an HTTP-verb method on
  a known test-client receiver (e.g. `client.get("/api/users")`).
- **Attribute-assignment RHS** — a literal assigned to any object
  attribute, directly (`obj.attr = "/path"`) or one call-indirection deep
  (`obj.attr = helper("/path")`). This is setup data attached to an object
  (often a mock), not a resource the test opens. A plain-identifier target
  (`path = "/path"`) is NOT carved out.
- **Membership assert** — the literal is the LHS needle of an `in`
  comparison asserted against a *dynamic* right-hand value
  (`assert "/login" in resp.text`, `assert "/x" in resp.headers["h"]`).
  An inline collection RHS (`assert "/x" in ["/a", "/b"]`) still fires.
- **Equality assert** — the literal is one operand of an `==` or `!=`
  comparison that is the asserted expression, and the other operand is a
  runtime value (`assert page_url("biston") == "/biston/"`,
  `assert nav_links() == ["/a", "https://b"]`). A program that produces
  paths and URLs states its expected output as literals; those are test
  data, not resources the test opens. Two literals compared to each other,
  an inline collection of literals as the other operand, ordering operators,
  and a `==` that is not the asserted expression itself all still fire.
- **Pytest fixture body** — strings inside a `@pytest.fixture` function.
- **URL kwarg value** (1c) — when the literal is the *value* of a keyword
  argument whose *name* is one of `url`, `endpoint`, `href`, `link`,
  `path`, `id`, or `name`. For example:

  ```python
  repo = build_repo(url="https://github.com/owner/repo")   # not flagged
  ```

- **Dict pair value with URL key** (1d) — when the literal is the *value*
  of a dict entry whose *key* is a string literal in the same name set.
  A non-string key (e.g. a variable) does NOT trigger this carve-out:

  ```python
  cfg = {"url": "https://github.com/owner/repo"}   # not flagged
  cfg = {KEY: "https://github.com/owner/repo"}     # still flagged
  ```

## Config

```toml
[tool.zorilla.rules.ZR005]
enabled = true
allowed_prefixes = ["http://localhost", "/tmp/zorilla-"]
extra_pure_callees = ["Path", "parse_locator"]
```

`allowed_prefixes` is a list of string prefixes that bypass the rule.
Matching is plain `str::starts_with`, case-sensitive, no globbing.
Empty strings are stripped at load time (an empty prefix would silence
every literal).

`extra_pure_callees` adds call targets to the built-in parse-only set
(`urlparse`, `urlsplit`, `urljoin`, `urldefrag`, `PurePath`,
`PurePosixPath`, `PureWindowsPath`). A literal that is a direct
positional argument of a listed callee is treated as parser input.
Matching is by the final identifier of the call target.

## Suppression

Inline. The finding points at the literal itself, which in a multi-line
call is not the call's first line; a directive on any line of the
statement holding the literal covers it, so the one a formatter moves to
the closing `)` still counts:

```python
url = "https://api.example.com"  # zorilla: ignore[ZR005] -- <reason>

response = client.fetch(
    "https://api.example.com/v1/things", timeout=5, retries=3
)  # zorilla: ignore[ZR005] -- <reason>
```

File-level:

```python
# zorilla: ignore-file
```
