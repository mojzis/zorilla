# ZR004 — assertion-roulette

## Why

When a test has many bare `assert` statements without messages and one of
them fails, the pytest traceback tells you "assertion failed at line N"
but not which *behavioural* claim broke. Debugging becomes a game of
roulette — which of the five asserts was the one you cared about? The
fix is either to collapse the asserts into one richer assertion, split
the test, or add messages.

The rule counts bare `assert` statements (no message) per test and fires
when the count strictly exceeds `max_asserts`. Asserts with a message
(`assert x, "msg"`) are exempt — the message removes the ambiguity.

Tests decorated with `@pytest.mark.skip` / `@pytest.mark.xfail` (at the
function or class level) are never flagged. The same applies to tests
whose **first real body statement** (after any leading docstring or
comments) is a runtime skip call — `self.skipTest(...)`, `self.skip(...)`,
or `pytest.skip(...)`. Such tests are unconditionally skipped; their
bare-assert count is academic. Note: `skipif`, bare `skip(...)`, and
non-`self`/`pytest` receivers are not matched.

## Positive example

```python
def test_all_fields():
    result = load()
    assert result.name == "alice"
    assert result.age == 30
    assert result.email == "a@b"
    assert result.role == "admin"
    assert result.active is True   # 5 bare asserts > default 4: fires
```

## Negative example

```python
def test_all_fields():
    result = load()
    assert result == User(
        name="alice", age=30, email="a@b", role="admin", active=True
    )
```

Or, keep the asserts but add messages:

```python
def test_all_fields():
    result = load()
    assert result.name == "alice", "name"
    assert result.age == 30, "age"
    assert result.email == "a@b", "email"
    assert result.role == "admin", "role"
    assert result.active is True, "active"
```

## Config

```toml
[tool.zorilla.rules.ZR004]
enabled = true
max_asserts = 4
```

`max_asserts` defaults to `4` — the rule fires on the 5th bare assert.

## Suppression

Inline (on one of the offending asserts):

```python
assert result.active is True  # zorilla: ignore[ZR004]
```

File-level:

```python
# zorilla: ignore-file
```
